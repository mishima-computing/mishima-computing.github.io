# Mishima Computing K.K. Design Language, Stage A

Status: ratification candidate for Stage B implementation. This document is the only design-language authority created by implementation contract `IC-20260612-004915-1951aad-stageA-design-language-v1`. It does not adopt, deploy, or modify the production site.

## 1. Scope and Invariants

This is a docs-only specification for the static GitHub Pages site at `mishima-computing.github.io`. Stage B must implement exactly this document unless the controller amends it before implementation.

Repository evidence:

- Current color tokens are dark-first and effect-led in `assets/css/style.css:4-74`.
- The current home page hardcodes `data-theme="dark"` in `index.html:2`; several other pages do the same.
- Current bilingual CSS hides one language while keeping both language strings in the DOM at `assets/css/style.css:215-219`.
- Current report modal body text is injected from `assets/js/app.js:138-215`, and the modal write target is `assets/js/app.js:228-240`.
- Current contact status and success strings are injected from `assets/js/app.js:322-325` and `assets/js/app.js:366-382`.
- ADR-0001 requires common header and footer navigation to be hardcoded in static HTML, not generated by JavaScript, so simple crawlers and AI agents can see page links without running scripts.

Hard invariants:

- Content immutability: no Stage B visible text changes, deletions, or new translations unless an appendix explicitly marks the string as a controller-gated static baseline amendment.
- Static ground truth: each HTML page's `<html>` element must hardcode `data-theme="light"`. JavaScript is enhancement only.
- No build step: baseline widely available HTML/CSS/JS only; no framework, SSG, bundler, runtime package, external script, or font CDN.
- ADR-0001 conformance: navigation and footer links remain static HTML on every nav-bearing page.
- Crawler and agent surfaces are functionally unchanged: `robots.txt`, `sitemap.xml`, `llms.txt`, `agent-readiness/manifest.json`, and existing JSON-LD behavior are untouched.
- Stage A has no adoption authority. Ratification happens only by merge.

## 2. Genre Grammar

Replace the current AI-startup landing-page grammar with a light-first, typography-led Japanese K.K. corporate trust grammar:

- White and warm off-white page grounds.
- Strong table setting for registry, public notice, plan, FAQ, and report metadata.
- Restrained blue-green water-line keyline as the only local motif.
- Typography and spacing carry hierarchy; decorative effects do not.
- Corporate trust anchors appear before technical spectacle: company registry, public notice, direct contact path, and static agent-readable navigation.

Forbidden implementation vocabulary and patterns:

| Forbidden item | Stage B rule |
| --- | --- |
| `glow` | Do not use in token names, class names, copy, comments, or effect names except when deleting current code. |
| `glass` | Do not use translucent-card or frosted-panel grammar; do not keep old token/class names. |
| `gradient-text` | Do not create gradient-filled text or gradient-text utility names. |
| `backdrop-blur` | Do not use `backdrop-filter` or blur-backed navigation/panels. |
| `orb` | Do not render decorative circular light fields or keep old orb classes. |
| `grid-bg` | Do not render grid backgrounds or keep the old grid background class. |
| inline style attributes | Stage B must remove `style="..."` attributes from edited page markup and move required declarations into CSS. |

The ban is about the shipped design language. If a migration comment must mention an old selector during deletion, the comment must not survive the final Stage B diff.

## 4. Typography

Use system fonts by default. A Japanese font may be self-hosted on GitHub Pages only if it is checked into the repository as a static asset and requires no build step. Do not use a font CDN.

Type scale:

| Role | CSS size | Line-height | Notes |
| --- | --- | --- | --- |
| Hero H1 | `clamp(2.25rem, 4.2vw, 4rem)` | `1.15` | Home only. |
| Page H1 | `clamp(2rem, 3.4vw, 3rem)` | `1.2` | Kessan, contact, article, privacy. |
| H2 | `clamp(1.5rem, 2.2vw, 2.25rem)` | `1.28` | Water-line keyline may sit below. |
| H3 | `clamp(1.125rem, 1.4vw, 1.5rem)` | `1.35` | Cards, tables, report subsections. |
| Body JA | `clamp(1rem, 0.35vw + 0.94rem, 1.125rem)` | `1.8` target, allowed `1.7-2.0` | JLReq-compatible long-form reading. |
| Body EN | `clamp(1rem, 0.3vw + 0.94rem, 1.1rem)` | `1.65` target, allowed `1.55-1.75` | Prevents over-loose Latin paragraphs. |
| Small / metadata | `clamp(0.875rem, 0.2vw + 0.84rem, 0.95rem)` | `1.45` | Dates, report tags, legal status. |
| Table text | `clamp(0.9375rem, 0.25vw + 0.9rem, 1rem)` | `1.65` | Dense corporate data. |

Measures:

- Latin body measure: `58ch-65ch`; legal/report article maximum `70ch`.
- Japanese body measure: `28-36em` for long paragraphs; tables can use full container width when label/value scanning is primary.
- Do not use negative letter-spacing. Letter spacing is `0`.
- Do not scale font size with viewport width outside the explicit `clamp()` bounds above.

JLReq basis: W3C Requirements for Japanese Text Layout describes Japanese line-gap design with larger line gaps for longer lines, commonly from half-em to one-em around the character frame and cautions against excess. This spec encodes that as JA body `line-height: 1.7-2.0`.

## 5. Spacing, Shape, and Motif

Spacing is an 8px modulo system:

| Token | Value | Use |
| --- | ---: | --- |
| `--space-1` | 8px | Tight inline gaps, table cell micro rhythm. |
| `--space-2` | 16px | Form groups, card internal pairs. |
| `--space-3` | 24px | Paragraph-to-control spacing. |
| `--space-4` | 32px | Section heading to body. |
| `--space-5` | 40px | Card padding desktop. |
| `--space-6` | 48px | Section internal bands. |
| `--space-8` | 64px | Section block spacing mobile/tablet. |
| `--space-10` | 80px | Desktop section spacing. |
| `--space-12` | 96px | Home hero top/bottom maximum. |

Shape:

- Border radius maximum: 8px for cards, controls, and tables.
- Legal register frame radius: 0px.
- Focus outline: 2px solid `--color-link`, offset 2px, never color-only.
- Tap targets: at least 24px by 24px per WCAG 2.2 AA Target Size (Minimum); primary nav and form controls should be 40px or taller where layout permits.

Single motif:

- The water-line keyline is a flat 2px or 3px horizontal rule using `--color-keyline`.
- Use at most one water-line keyline per section title or legal table header.
- Do not use waves, mesh, background patterns, lighting fields, or animated motif elements.

### 6.6 Kessan Legal Register Frame

Name: `kessan-legal-register`.

This frame is governed by public-notice gravity, not marketing emphasis. Basis: Companies Act Article 440 requires public notice of financial statements; Article 440(3) allows continued public availability of balance-sheet information by electronic or magnetic means for five years. The Ministry of Justice electronic public notice guidance also distinguishes settlement/public financial notices and their electronic publication treatment.

Rules:

- No card chrome.
- No animation.
- No decorative imagery.
- No shadows.
- No rounded frame.
- Table-set layout with clear label/value alignment.
- The current strings on `/kessan/` remain on `/kessan/`.
- Leave headroom for multi-year notice accumulation: each fiscal year is one table/list row group with year, document title, status, publication date when available, and link/file cell when available.
- The current first-term preparation state remains visible until legal content is available; no invented balance-sheet data.

## 7. Motion

Allowed properties: `transform` and `opacity` only. Color, background, border-color, height, width, blur, shadow, and layout-position animation are not allowed.

Timing ranges:

- Control feedback: `120-180ms`.
- Navigation underline or keyline response: `140-220ms`.
- Card/link lift, if used: `160-240ms`, maximum translate distance 2px.
- Page/section reveal, if retained: `220-320ms`, opacity and translate only.

Every nontrivial motion path must have `prefers-reduced-motion` parity:

- Reduced motion sets transform distance to 0 and duration to the lower edge of the range or disables the transition.
- Hover/focus information must remain available without motion.
- No claim may state that motion itself improves corporate trust.

## 8. Feel Surface Commitments

Exactly four feel surfaces are declared. No other feel proof claims are made.

proves: nav response is acceptable only if header links expose static `href`s, a visible focus state, and a non-motion active/current state on every nav-bearing page.

proves: section scanability is acceptable only if H2/H3 hierarchy, table labels, report tags, and water-line keylines allow a reviewer to identify company facts, service areas, reports, public notice, contact, and privacy policy without reading body paragraphs.

proves: contact affordance clarity is acceptable only if the primary contact action is a real link or submit button with visible label text in both JA and EN and no hidden dependency on decorative icons.

proves: toggle feedback is acceptable only if language and theme controls expose their current/next state through visible text or accessible label, preserve focus, and still leave light/JA static HTML readable with JavaScript disabled.

## 9. Theme and Language Behavior

Theme:

- Each page starts as static light HTML: `<html lang="ja" data-theme="light">`.
- `:root` defines light tokens. `[data-theme="dark"]` overrides them.
- If `localStorage.theme` exists, JavaScript may switch to the saved theme as enhancement. The no-JS ground truth remains light.
- FOUC rule: no content may disappear during theme initialization; a brief light-to-dark token switch is acceptable only after first paint, and only if all text remains readable before and after the switch.
- Stage B may simplify the current theme controller fallback from dark to light. It must not expand `assets/js/app.js` feature scope.

Language:

- Keep the language toggle.
- Default static HTML is Japanese (`lang="ja"`), with English strings still present in the DOM in their current `lang="en"` spans.
- Do not use a dual-visible JA/EN default. It is too dense for the corporate trust grammar.
- JavaScript may switch `html[lang]`, toggle visible language, and update form placeholder text.
- Static DOM-text extraction sees both language strings. Visual layout may show one language at a time.

## 12. Accessibility Commitments

- WCAG 2.2 AA text contrast: all normal text >= 4.5:1; large text and non-text >= 3:1.
- WCAG 2.2 target size: pointer targets at least 24px by 24px or meet the documented spacing/equivalent exceptions.
- Headings maintain document outline order; visual heading scale does not override semantic rank.
- Links are identifiable without relying on color alone: underline, keyline, icon, or strong focus state.
- Forms have visible labels, programmatic labels, and no placeholder-only fields.
- Language spans retain `lang="en"` for English and Japanese page root remains `lang="ja"` by default.
- Theme and language toggles are buttons with accessible labels and visible focus.
- Dark variant is a first-class contrast variant, not an afterthought.

- Contrast token lint for text/non-text ratios.
- Nav parity check across the seven nav-bearing pages.
- Visible static DOM text diff gate per page.

## Appendix A. Gate Semantics and JS-Injected Strings

### A.1 Static DOM-Text Gate

Stage B text check definition:

1. For each current HTML page, parse static HTML from disk.
2. Extract body text from static DOM without executing JavaScript.
3. Ignore `script`, `style`, `noscript`, SVG path geometry, and comments.
4. Include visible text nodes, visible form placeholders, and image alt text only when the image is visible and the alt is the user-facing substitute.
5. Normalize whitespace to single spaces, trim ends, and compare per page.
6. The diff must be empty per page, except for a controller-approved baseline amendment for Appendix A strings.

This gate intentionally evaluates page-by-page text sets. Moving text from `/` to `/about/`, from `/` to `/reports/`, or from modal JavaScript into a different route fails unless the controller signs a gate amendment before Stage B.
